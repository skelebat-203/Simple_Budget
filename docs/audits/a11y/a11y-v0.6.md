## Fixes

- **A1** `src/components/Backup.tsx`: a visually hidden `<label htmlFor="backup-file">Backup file (.json)</label>`, as the Import section already has. Backup dialog now 100.
- **A2** `src/App.css`: `.banner-success .banner-title` uses the page text color like the warning and info banners; the icon and border carry the green. Light-theme ratios computed: success 4.38, warning 4.32, info 3.62 as text on their tints; page text on the tints is about 15:1.
- **A3** `src/App.css`: `.option:hover`, `.option[aria-selected="true"]`, `.name-link:hover` and `.expander:hover` switch to the page text color on the grey hover background (`--color-border`, #e5e7eb). Before: lighter green 4.05, lighter orange 4.18, even-lighter orange 4.06. After: 14:1. The grey background still marks the active option. Lighthouse run with the pointer over an option and over an item name: 100.
- **A4** `src/App.css`, `src/styles/tokens.css`: `.banner li a` is `inline-block` with `min-height: var(--size-target-min)` (new token, 24px).
- **A5** `src/screens/BudgetSetup.tsx`: the row name cell and the Expander use `setup_name` and `setup_expand` id prefixes (the highlight dialog already uses `hl_`). Duplicate ids with Budget setup open: 0 at all three widths.

## A6 — wizard group rows (fixed)

`src/screens/Onboarding.tsx` step 3 used `<details><summary><label><input type="checkbox"> Group</label></summary>`: a disclosure button holding a checkbox. The checkbox was 13×13px, its area overlapped the summary, and Tab did not move past a collapsed group. Decided by the human: the group row is now two separate controls, no nesting. The checkbox alone selects the group (44×44px, accessible name "Select all in {group}"); the group name is an `Expander` button (`aria-expanded`) that fills the rest of the row to the container's right edge. The two are 2px apart (`--space-hairline`; the human chose this over the 10px control-margin rule in `components.md`). Open state is kept per group; the first two start open as before. Checked with `wizard3.mjs`: 35 Tab stops through all groups (collapsed ones included), no trap, gap 2px, name button reaches the row's right edge, at 1280, 375 and 320px.

## Scripted checks (pass)

- **Reflow**: no sideways page scroll in any state at 320, 375 and 1280px.
- **Live region**: never more than one live region in the page (0 before the first message, 1 after), also with several dialogs stacked.
- **Headings and title**: one visible `h1` in every state; title "Simple Budget".
- **Focus**: a Tab walk in each dialog stays inside the topmost dialog; every stop shows a focus ring (outline or box shadow on the control or its label); none lands off screen.
- **Dialog focus** (1280px, `focus.mjs`): for Help wizard, Backup, Day purchase Edit, highlight, Add/Subtract and Rename: focus moves into the dialog on open, 25 Tab presses never leave it, Escape closes it, and focus returns to the control that opened it (30 of 30 checks).
- **Target size**: only one control under 24px remains: the inline "Show them" button inside a sentence in the import review (exempt as an inline target, 2.5.8).
- **Console and CSP**: no console error or warning, no `securitypolicyviolation`, in any run.

## Not run in this pass

200% and 400% zoom, text spacing overrides (1.4.12), forced colors, reduced motion, and the sticky Save and Import footers at zoom (CLAUDE.md overrides). The Range control (Day, Week, Month, Annual) is a group of `aria-pressed` buttons; `components.md` asks for radios in a Toggle of 2–3 options, and this one has four, so it was left as built.
