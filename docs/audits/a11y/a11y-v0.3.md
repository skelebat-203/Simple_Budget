## Scripted keyboard and focus checks (pass)

- **Tabs** (from 640px): arrow keys with wrap, Home/End, one tab stop, Tab moves to
  Setup Budget then into the panel; form values survive a tab switch.
- **Screens menu** (below 640px): Enter/Down opens on the current screen, Up/Down move,
  Enter picks, Escape closes and returns focus to the button; picking a screen focuses
  its heading; Setup Budget returns focus to the button on close.
- **Item list**: arrow keys set `aria-activedescendant`; headings are group labels,
  not options; repeated names get "Name, Parent" accessible names.
- **Add purchase**: 3 or fewer errors focus the first errant field; Where? required.
- **Budget setup treegrid**: one tab stop; Up/Down/Home/End/Ctrl+Home/End move
  between cells; Right/Left expand, collapse and go to the parent row; Enter/F2 edits
  a cell; Escape returns to the cell without closing the dialog; Space toggles a
  row's checkbox; Tab leaves the grid; Move up/down keeps focus on the button; Save
  and Cancel return focus to the opener.
- **Budget tables (treegrid)**: every body row has `aria-level`; the same keys as
  Budget setup; Enter reaches a row's action buttons and Tab moves between them.
- **Table actions**: Day delete confirmation focuses Cancel; after a delete focus
  moves to the next purchase, the previous one, or the table's first cell. Add value and
  Rename focus their field; Escape cancels; results are announced in the table's
  status region.
- **Responsive**: no sideways page scroll at 320, 640 and 1000px (tables scroll in
  their own box, at most screen height − 24px); every control at least 44×44px or
  inside a 44×44 label; 3px focus outline; no duplicate ids; no heading skips.
