# Accessibility pass — v0.5

Findings from the human review of 2026-11-04 (UI/UX and accessibility). The Lighthouse
and scripted keyboard checks for v0.5 still need to run once the open finding is closed.

## Findings

| # | Finding | Status |
| --- | --- | --- |
| 1 | Audit the live regions in the DOM; if more than one, use a single polite region and inject every message into it | Fixed (v0.5.8) |
| 2 | Arrow-key navigation in the Day, Week, Month and Annual tables blocks keyboard access to the controls inside cells (second request) | Open: options sent to the human, awaiting a choice |
| 3 | Budget setup: the Preview table header overlaps the Cancel / Save buttons | Fixed (v0.5.8) |

## 1. Live regions

Before: 13 elements with `role="status"` or `role="alert"` (Notices, Backup, Budget table
status and error, Add purchase, Budget setup, Onboarding, multi-select count, error
summary, startup error). Each announced on its own.

After: one `<div id="live-region" role="status" aria-live="polite" aria-atomic="true">`
(`src/components/ui/announcer.ts`). Every message goes in through `announce()` /
`useAnnounce()`; visible copies of the messages are plain text with no live role.
Because an open modal dialog makes everything outside it inert, the region moves into
the topmost open dialog before each message and back to `<body>` when none is open.

Checked in the browser: exactly one live-region element in the page after an Add purchase
error, after a save, and inside the open Budget setup dialog (where "Added Side gig to
Income." was injected).

## 3. Preview header over the footer

The sticky table header (`z-index: 1`) painted above the sticky dialog footer, which had
no `z-index`. The footer now has `z-index: 5`. Checked: the element at both footer button
positions is the footer, with the dialog scrolled to the Preview.
