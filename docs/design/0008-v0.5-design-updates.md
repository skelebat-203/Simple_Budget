# 0008 — v0.5 design updates

Human decisions of 2026-11-03 from the v0.4 review. Where this doc and `0007`
differ, this doc wins (each conflict is named below).

## 1. Table expanders

- Every expand/collapse control in every table (Budget setup; Budget Day, Week,
  Month, Annual) is a real `<button>` with `aria-expanded`, reachable by Tab.
- The button holds the icon and the row name: `▸ Expenses` / `▾ Expenses`. The
  icon is decorative (`aria-hidden`); the name is the button's text.

## 2. Budget setup keyboard

- Remove the table's own keyboard shortcuts (arrow keys, Home/End, Enter/F2 to
  edit, Escape back to the cell). Every field and button inside the table is a
  normal Tab stop.
- Keep `role="treegrid"` and `aria-level` / `aria-expanded` on rows.
- Screen reader table navigation (e.g. NVDA/JAWS table keys, VoiceOver table
  commands) must keep working; the accessibility pass tests it.
- Note for the build: the ARIA treegrid pattern expects author-provided arrow-key
  navigation, and some screen readers switch to focus mode inside it. If testing
  shows table keys stop working, bring it back to the human before changing the role.
- **Supersedes** the Budget setup part of the `0007` §10 keyboard model. The Budget
  tables (Day, Week, Month, Annual) keep it.

## 3. Due dates and recurrence

### 3.1 Placement in the tables

- An estimate with a recurrence **and** a due date is not spread across the
  range. Its full amount goes on the column holding the expected payment day
  (Week day, Month week, Annual month), and in that period's total.
- An estimate without a due date is spread as today (v0.4 scaling).
- The estimate is the amount **per payment** (decided 2026-11-03). Bi-monthly puts the
  full estimate on each of its two payment days; Every 2 weeks puts it every 14 days
  counting from its next pay/due date.

### 3.2 Due date field by recurrence (Budget setup)

| Recurrence | Due date control |
| --- | --- |
| Daily | None |
| Weekly | Dropdown of weekdays |
| Every 2 weeks | Date picker named **Next pay date** (Income) or **Next due date** (Savings, Expenses); payments fall every 14 days from it |
| Bi-monthly (twice a month) | Two dropdowns: **1st payment** (1–15) and **2nd payment** (16–27, Last) |
| Monthly | Dropdown: 1–27, Last |
| Quarterly, Annual | Full date picker (date of the next payment) |

- "Last" means the last day of the month.
- The Budget setup column heading "Due date" is renamed **Schedule** (decided 2026-11-03).
- Changing the recurrence clears a due date that no longer fits.

## 4. Week, Month and Annual column borders

- A solid border between each time period (day, week or month), including before
  Total. No border between a period's Est. and Act. columns.

## 5. Date navigation

- Previous and Next use left and right chevron icons; their accessible names
  stay "Previous {unit}" and "Next {unit}".
- The range-title button opens the browser's calendar directly, not a popover
  holding a date field. **Supersedes** the v0.4 popover (this restates `0007`
  §9.5: "opens the same date picker the Date field uses").

## 6. Settings: rewards and notifications

Human decisions of 2026-11-03.

- Two checkboxes in Budget setup: **Rewards** (default on) and **Daily reminder**
  (default off). Saved with Budget setup's Save.
- Turning the reminder on asks the browser for notification permission from that
  click. If permission is denied or unsupported, the box stays off and says why.
- v0.5 builds the toggle, the permission request and a `sendReminder()` hook
  ("Did you add all your purchases?"). **Nothing schedules it.** A web app cannot
  fire a notification at a set time while closed; the daily end-of-day ping needs
  something outside the web app (a phone reminder, or the Capacitor build in
  Post v1.0). The toggle does not wait for the phone build.

## 7. Reward hooks

- The final reward design waits on user testing. v0.5 builds the hooks:
  `fireReward()` plays one reward from a list (`REWARDS`); adding a design means
  adding an entry (image + sound).
- Placeholder rewards: a simple cute image with a short animation and a short
  chime. Fired when a purchase or a Week/Month value is saved, only when Rewards is on.
- Respects `prefers-reduced-motion` (image shows without movement). The reward is
  decorative: hidden from screen readers; the existing "Saved" status is the announcement.
- Budget setup has a **Preview reward** button for testing.

## 8. Onboarding and help

- A questionnaire dialog shows on first run (no purchases, not yet finished or
  skipped). It can be **skipped**.
- A **?** help button to the right of the "Simple Budget" heading reopens it at any time.
- Questions (from `0004-table-design.md` Onboarding):
  1. How often do you get paid? Sets the Recurrence of every Income item (pay
     frequency is the Income items' Recurrence field in Budget setup).
  2. Add spending and savings categories? **No** leaves selections alone. **Yes**
     shows a multi-select with autocomplete over every Savings and Expenses item,
     starting from the current selection. Typing a name that matches nothing
     offers "Add" to create it under Expenses.
- Done stores the answers; the tables update from the selected items.
