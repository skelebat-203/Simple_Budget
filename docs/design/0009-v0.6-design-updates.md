# 0009 — v0.6 design updates

Human requests of 2026-11-04 from the v0.5 review. The wizard (§1) is decided
(`0010-onboarding-wizard-prototype.html`) and replaces the `0008` §8 single-dialog
questionnaire. The highlight (§3) is decided (`0011-highlight-prototype.html`).

## 1. Onboarding wizard

A dialog wizard with a progress bar (step X of 3).

1. How often do you get paid? (same options as `0008` §8)
2. Add spending and savings categories, or use presets? Buttons **Use presets**
   (primary) and **Add categories**. Use presets closes the wizard.
3. A checkbox list of every preloaded category and subcategory. An **Advanced setup**
   button to the right opens Budget setup.

Decided 2026-11-04 (from `0010`):
- Step 3: **Back** at the left, **Done** at the right, **Advanced setup** beside the list.
- The list is grouped by category and collapsible.
- No "Add your own" box in the wizard (it replaces the `0008` §8 box); adding names
  stays in Budget setup (Advanced setup).
- Step 2 does not list the presets. Its help text is "You can change presets later in
  Budget setup."
- Advanced setup closes the wizard.
- The wizard opens on first run (empty database), as the v0.5 questionnaire does.

## 2. Budget setup: Add buttons

The four "Create in {Category}" field rows are replaced by **Add** buttons, one per
category. Selecting one shows that category's "Create in" and "Add to" fields above the
button, with a **Save** button to the right of "Add to"; focus moves to the first field and
"Fields added above" is announced through the app's single live region. While the fields
show, the button reads **Cancel** and hides them (decided 2026-11-04). Save also hides
them and returns focus to Add. A duplicate name reads `Invalid: “{name}” already exists in
{category}`.

## 3. Highlight

- Clicking an item name (purchase, item, category or subcategory) in Day, Week, Month
  or Annual opens a dialog showing that row and its children, with the same functions
  the table row has (`0007` §9, Edit menu below).
- Expand/collapse moves to the chevron button alone (`0008` §1 stays; the name no
  longer toggles).
- The dialog shows the row **as it appears in the table being viewed** (decided
  2026-11-04): in Day, an item's purchases are its children and are listed; in Week,
  Month and Annual no purchases are listed because those tables do not show them.
- The name is a button with a **2px dotted underline** (decided 2026-11-04; a 1px
  dotted underline was rejected as unclear; `0011` shows other options that were
  not chosen).
- Hover styling is added to buttons and links across the app (roadmap item).
- Delete in the dialog asks for confirmation first and is hidden in Month and Annual
  (confirmed). A purchase row in Day opens the purchase dialog (§4.1; decided 2026-11-04).
  `0011` shows Week only and is not updated for Day.
- Prototype compares the current table with the highlight.

## 4. Edit menu (Day, Week, Month; not Annual)

- The row's "Actions" menu is renamed **Edit**.
- Items: **Rename**, **Add/Subtract** (Day: **New purchase**), **Delete** (Day and Week
  only). Each opens a dialog, not an inline row form. Description is part of the Day
  purchase dialog (§4.1); item rows have no Description.
- All dialogs open with focus on the dialog container (decided 2026-11-04).
- Rename: if the new name belongs to a different category or subcategory, the item moves
  there, chosen with a Category select in the dialog (confirmed 2026-11-04). Rename is
  not offered for top-level categories (Income, Savings, Expenses). The dialog shows a
  warning banner, "This changes ALL historic records." (warning colour `--color-warn`).
  Renaming within the highlight dialog works the same.
- Description: stored on each purchase; see the roadmap's "Optional description field
  below Amount" and the Day table (Description shows only there, under the purchase label).

### 4.1 Add/Subtract behavior (decided 2026-11-04)

- Amount fields accept typed expressions (`12.50+3`); see the roadmap item.
- **Day, category row:** a **New purchase** button opens the dialog and adds a new
  purchase to that category.
- **Day, purchase row:** an **Edit** button (not a menu), and the purchase name, open one
  dialog (decided 2026-11-04). Heading "Purchase, {time}, {item}"; lines "Amount:" and
  "Date:"; then the Add purchase form prepopulated (Item, Category and Use in future when
  the item is new, Amount, Description, Date; the form code is shared with Add purchase).
  Footer: **Cancel** and **Save** at the left, **Delete** at the right (asks first). Save
  removes the existing record and adds a new one with the new data.
- **Week and Month, item row:** Add/Subtract adds to or subtracts from the existing
  total. It is saved as a new positive or negative purchase (as `0007` §9.2 "Add
  value"), so the total moves by the amount entered. The dialog includes a **date
  picker limited to the period being viewed** (decided 2026-11-04). Its default is
  today when today is in the range, otherwise the range's last day (`0007` §9.2).
  The date can only be changed within the range.
- **Supersedes** `0007` §9.1 ("No editing of a purchase") and §9.4 (amount
  correction post v1.0) for the amount only. Correcting a purchase's date stays
  post v1.0.

## 5. Help dialog

Decided 2026-11-08:

- The "?" button launches the onboarding wizard, as today; the wizard also opens by
  itself on first load.
- The wizard footer offers "Advanced options" at the bottom right (opens Budget setup).
  Layout as `images/0012/g7-option-1.jpg` (Cancel/Back and Next together at left, the

## 6. Charity purchases (decided 2026-11-04)

Replaces the Charity part of `0007` §2.1 and the "Charity › Miscellaneous" routing in
`0004`. Medical keeps its Miscellaneous routing.

- **Solo state:** while Miscellaneous is Charity's only *selected* child (the default
  after onboarding), Charity takes purchases itself and can be picked in the Item
  dropdown. Purchases are listed under "Charity"; Miscellaneous is not offered.
- **Gaining an item:** when any other Charity child becomes selected (in Budget setup),
  or a new item is added under Charity (Add purchase; it counts as selected), every
  purchase on Charity moves to **Charity › Miscellaneous** in the same save
  (created if missing). Charity then only totals its children and cannot be picked.
- **For good (decided 2026-11-04):** once Charity has gained a child it stays a roll-up
  (stored as `rollup` on Charity), even if the child is deselected later. Charity is never
  picked again; purchases always go to Miscellaneous or another child. Any purchase found
  on Charity after that moves to Miscellaneous on the next save.
- **Message:** when purchases move, an info banner and one live-region message say so
  ("Your 2 Charity purchases moved to Charity › Miscellaneous. Charity now totals its
  items."). Add purchase shows it under the Saved banner; Budget setup shows it at the top
  of the page after the dialog closes, with a "Got it" button.
- **Estimate:** unchanged; Miscellaneous holds it as the solo item does today.
- Charity is found by name (under Expenses); a renamed Charity is not covered.
