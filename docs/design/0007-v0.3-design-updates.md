# v0.3 design updates

Source: `docs/human_scratch_files/stuff.md` (human notes, refined here). Builds
on `0004-table-design.md` and `0006-prototype.html`. Per doc precedence, this
doc wins where it conflicts with a lower-numbered one; each conflict is listed
under **Supersedes** so it is never silent.

Status: **draft — awaiting human review.** Items marked *Open* are not decided
and do not override anything yet.

## 1. Calendar settings

### 1.1 Week start
- Setting: the day a week starts on. Any day of the week. **Default: Sunday.**
- Applies to the Week table and the week columns inside the Month table.

### 1.2 Month boundaries
- Setting with two options:
  - **Calendar month** — the 1st to the last day of the month (current behavior).
  - **Whole weeks** — the month starts at the start of the week containing the
    1st and ends at the end of the week containing the last day.
- *Open:* default option. Proposal: Calendar month.
- *Open:* where the settings live (Budget setup overlay, or a separate Settings
  screen).

## 2. Recurrence and estimates

### 2.1 New recurrence options
- Debt, Utilities and Subscriptions items gain **Quarterly** and **Annual**.
- Full list for those groups: Daily, Weekly, Every 2 weeks, Bi-monthly (twice a
  month), Monthly, Quarterly, Annual.
- Income keeps the existing list (no Quarterly or Annual).
- *Open:* should the Add form's Recurrence dropdown (0004) offer Quarterly and
  Annual too, or only for those three groups?

### 2.2 Scaling estimates to the table range
- The Week and Month tables scale each estimate from its recurrence to the
  range shown (divide or multiply). Example: a $120 quarterly bill shows $40
  in a month and about $9.23 in a week.
- This extends the existing per-period conversion to the two new recurrences.

## 3. Table views

### 3.1 Day table — actuals only
- The Day table shows **only that day's transactions**. No Est. column.
- **Supersedes** `0004` Day layout (Row 1: Est. and Act.).

### 3.2 Monthly actuals table (new)
- A new table showing the **actual total for each item for the month**.
- **No estimates.**
- *Open:* is this a new range option beside Day / Week / Month, or a second
  table on the Month view? And does it break totals down by week, or show one
  total per item?

## 4. Budget setup overlay

- **Save** closes the overlay and is placed on the **right**.
- A **Cancel** button on the **left** closes without saving.
- **Supersedes** `0006-prototype.html` and the current build, where Save keeps
  the overlay open and collapses the item list (from the earlier `stuff.md`
  notes).
- *Open:* with Save closing the overlay, the "collapse but do not remove the
  list on save" rule no longer applies. Confirm it is dropped.

## 5. Item control — selected items first

### 5.1 Default list
- Once the user has picked items in Budget setup, the Item list shows **only
  those items** before the user types.
- As soon as the user types, autocomplete searches the **full** list
  (preloaded and custom).

### 5.2 Typing a new item
When the typed text matches no existing item:

1. A **Category** dropdown appears.
   - It lists categories and subcategories.
   - Categories are headings only (not selectable); they show where each
     subcategory sits in the budget.
2. If the user types a **new subcategory** name in Category, it is saved, and a
   **Where?** dropdown appears directly below with: Income, Savings, Expenses.
3. A **Use in future** checkbox sits to the **left** of Save.
   - **Save is always on the right** of the form.
   - Checked: the new item (and new subcategory) is selected for regular use.
4. The new item, or new subcategory and item pair, **always appears in the
   budget tables**, whether or not *Use in future* is checked.

- *Open:* Income and Savings currently have no subcategories (Pay, Incidental
  Income and Taxes take amounts directly). A new subcategory under Income or
  Savings would change that structure in `0004`. Confirm this is intended.
- *Open:* does *Use in future* default to checked or unchecked?

## 6. Reordering

- Users can reorder items and subcategories, probably in the Budget setup
  overlay.
- Limits:
  - Items can move into a different subcategory **within the same category**.
  - Items and subcategories **cannot** move to a different category.
- The order is saved and used by the Item list and every table.
- *Open:* interaction (drag and drop needs a keyboard alternative per
  `digital_accessibility.md`; move up / move down buttons meet it directly).
